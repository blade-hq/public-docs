## 为什么开发插件

当你要把业务系统查询、文档处理或数据分析交给用户使用时，可以把相关能力做成一个插件。用户安装并在会话中激活它，按需要填写账号配置，就能在对话里调用工具，或通过交互卡片选择数据。

插件负责把使用过程中需要的内容组织在一起：业务指引、可执行工具、配置声明和界面资源都随包交付。并非每个插件都需要全部组件；一个只提供 Skill 的插件也可以成立。

## Plugin、Solution 与 Skill 怎么选

| 形式 | 适合的需求 | 用户使用方式 |
| --- | --- | --- |
| Plugin | 交付有完整使用体验的业务能力 | 同一会话可以同时激活多个插件，组合使用 |
| Solution | 提供面向特定场景的一整套解决方案 | 同一会话只能选择一个 Solution |
| Skill | 普通用户自行开发和上传轻量能力 | 添加单个技能，配置和交互等端到端体验需要另外组织 |

例如，用户可以在一次对话中同时启用数据查询和报告生成插件，先查数据再写报告。插件开发不要求先创建 Solution 或业务角色。

## 插件能包含什么

| 组件 | 入口 | 作用 |
| --- | --- | --- |
| 插件清单 | `plugin.json` | 声明身份、版本及展示信息 |
| Skill | `skills/<技能目录>/SKILL.md` | 告诉智能体何时使用能力、怎样完成业务任务 |
| MCP 服务 | `mcp.json` | 提供可发现和调用的程序工具 |
| 用户配置 | `cn.com.bladeai.agent/config.schema.json` | 声明由 BA 展示和校验的配置表单 |
| MCP Apps | MCP 工具关联的 `ui://` 资源 | 提供选择、预览及提交信息的交互卡片 |

BA 按 [Agent Plugins 1.0.0 规范](https://agent-plugins.org/specification)处理清单与 MCP 声明；Blade 专属展示字段放在 `extensions["cn.com.bladeai.agent"]` 中。其他客户端支持的插件组件，不代表 BA 也会加载。

:::note[适用基线]
本指南核对于 2026-09-10，BA 代码基线为 `75db2d5c`，Hub 为 `5c8da9d0`。示例以沙盒会话为前提，插件 MCP 当前不支持本地电脑 daemon 会话；MCP 支持 stdio 和 Streamable HTTP，不支持 SSE。

这份 Hub 基线尚不允许上传 `cn.com.bladeai.agent/` 目录和 `.html` 文件：基础教程可以通过 Hub 发布，配置和 Apps 章节需要先具备相应的包分发支持。具体限制见[发布、安装与版本更新](../publish/#发布前检查)。
:::

## 用户如何使用插件

1. 在 Hub 上传自己的插件，或找到可见的内置插件，点击安装。
2. 在 BA 沙盒会话的插件列表里勾选需要的插件，可以同时选中多个。
3. 声明了配置的插件会提供配置入口，用户填写并保存后再使用。
4. 用户提出业务问题，智能体按需读取技能、调用工具；带界面的工具可以显示交互卡片。

Hub 安装表示插件进入账号的安装列表，会话勾选表示本次对话选择使用它，准备成功才表示相应能力可用。网络错误或缺少配置时，选择可以保留，但能力尚未就绪。

取消勾选会停止向智能体呈现该插件的能力索引，不删除已准备文件，也不是撤销业务系统权限的方式。用户配置按用户和插件共享，另开会话仍可使用；插件中的业务服务应自行验证每次请求的身份与权限。

## 本指南的开发示例

本指南面向能编写 Python 或 JavaScript 的插件作者，以 `business-data` 业务数据查询插件为例，逐步加入工具、技能、配置和界面。

开发完成并满足上述分发条件后，用户可以安装并激活“业务数据”插件，按需填写账号配置，在对话中打开数据选择卡片，选择销售或库存并预览结果，再将选中的数据加入待发送区，请智能体汇总分析。整个过程无需用户编写代码或手动调用接口。

从[开发第一个插件](../quickstart/)开始，先跑通一次演示数据查询。
